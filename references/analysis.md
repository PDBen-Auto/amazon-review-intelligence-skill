# 客诉/评论分析报告 Skill

## 目标

将 Amazon 评论、VOC 买家之声、客服工单、销售/退款数据等整合为一份可直接打开的交互式 HTML 报告。报告必须同时呈现：

- 产品基础信息：产品图片、标题、品牌、ASIN、Listing 链接、链接评分、评论数
- 负面反馈 TOP10：1-3 星评论或用户指定的负面样本
- 正面反馈 TOP10：4-5 星评论或用户指定的正面样本
- 每个 TOP 项：一级原因/卖点、二级拆解、可点击查看原声与中文译文
- 适配性/兼容性分析：有相关数据时展示
- 改进建议优先级矩阵：结合负面痛点和正面卖点

## 数据整理

### 必需字段

| 数据类型 | 字段 | 说明 |
|---|---|---|
| 评论/反馈 | 星级、标题、原文、日期、来源 | Amazon 评论/VOC/客诉均可 |
| 翻译 | 中文译文 | 原文非中文时必须提供或生成简短译文 |
| 产品信息 | ASIN/链接/标题/品牌/图片/评分/评论数 | 可从用户数据或公开页面获取；获取不到时标注“未获取” |

### 可选字段

| 数据类型 | 用途 |
|---|---|
| 月度销售额/销量 | 销售趋势图 |
| 月度退款率/盈利率 | 退款与盈利趋势 |
| 车型/SKU/兼容记录 | 适配性分析 |

## 产品基础信息

生成报告前尽量获取并展示：

```text
product_title: 产品标题
brand: 品牌
asin: ASIN（ASIN 必须加 Listing 超链接）
listing_url: Amazon/平台链接
rating: 链接评分
review_count: 链接评论数
image: 产品主图
```

规则：

- ASIN 在报告顶部和产品信息卡中都要加超链接。
- 产品主图优先使用用户提供图片；其次从 Listing 获取；如果外链可能失效或本地 HTML 无法显示，下载图片并以内嵌 data URI 或本地同目录资源方式写入报告。
- 如果评分、评论数、品牌或图片无法可靠获取，不要编造，显示“未获取”。

## 分类口径

### 负面反馈

- 默认使用 1-3 星评论。
- 若用户提供 VOC/客诉但无星级，将其并入负面反馈。
- 输出负面反馈 TOP10。

### 正面反馈

- 默认使用 4-5 星评论。
- 输出正面反馈 TOP10。
- 正面分类应围绕用户认可的卖点和使用场景，例如：降温/风量满意、儿童/婴儿适用、安装方便、静音、宠物场景、夏季长途、性价比、外观小巧、USB 供电便利等。需按具体产品调整。

### 百分比归一

正面和负面的 TOP10 都必须使用“单条评论只归入一个主类”的主类归因口径。

- 每条负面评论只归入 1 个最主要负面问题。
- 每条正面评论只归入 1 个最主要正面卖点。
- 负面 TOP 项百分比合计应接近或等于 100%。
- 正面 TOP 项百分比合计应接近或等于 100%。
- 如果有效主类不足 10 个，可以展示少于 10 个 TOP 项，但合计仍应为 100%。
- 若主类超过 10 个，将第 10 项合并为“其他负面体验”或“其他正面反馈”。

## TOP 项数据结构

每个正面/负面 TOP 项包含：

```text
issue:    问题/卖点名称（简洁，≤12字）
count:    归入该主类的评论数
pct:      占该组评论百分比（该组 TOP 项合计约100%）
cause:    原因分析或卖点解释（2-4句）
suggest:  建议动作（2-4条）
```

每个 TOP 项再拆分 2-4 个二级问题/卖点：

```text
name:    子类名称（≤15字）
cnt:     该子类归入评论数
kws:     匹配关键词数组
detail:  子类解释（1-2句）
```

二级拆分可多标签辅助解释，但展示时应尽量使子类合计接近该主类 count。

## 原声展示

每条原声包含：

- 星级
- 来源标注（亚马逊评论 / 买家之声 / 客诉）
- 日期
- 标题
- 原文
- 中文翻译
- 原评论链接（有则展示）

隐私处理：评论中出现真实姓名时替换为“用户”。

## 适配性分析

如果评论中出现车型、SKU、头枕、尺寸、兼容性、安装结构等信息，生成适配性分析 Tab：

```text
不适配/风险场景：
  car/sku: 车型、SKU 或场景
  note:    不适配原因
  cnt:     频次

适配良好场景：
  car/sku: 车型、SKU 或场景
  note:    适配说明
  cnt:     好评提及次数
```

同时给出根因判断和改进建议。

## 改进建议矩阵

输出 6-10 条建议，分级：

| 级别 | 标准 |
|---|---|
| CRITICAL | 影响面大、直接导致退货/差评，或安全风险 |
| HIGH | 影响 15-40% 评论，或严重影响体验/转化 |
| MEDIUM | 影响 5-15% 评论，改进 ROI 明显 |
| LOW | 低频优化或锦上添花 |

建议必须同时利用负面痛点和正面卖点，例如：

- 修复质量失效/误导/适配/安全问题
- 放大正面高频卖点（儿童、宠物、夏季、静音、安装便利等）
- 避免正面卖点与负面预期冲突（如 USB 供电便利 vs 无电池误解）

## HTML 输出规范

按照 `html-template.md` 的结构生成单文件 HTML。

必须满足：

- 单文件 HTML，CSS + JS 内嵌；无需外部接口。
- 响应式布局，移动端可用。
- Header 展示产品名、ASIN 超链接、市场、分析日期、数据来源。
- 数据概览展示产品基础信息卡片。
- 导航 Tab 至少包含：数据概览、负面反馈 TOP10、正面反馈 TOP10、适配性分析（有数据时）、改进建议。
- 点击 TOP 行展开三栏卡片（频次/原因/建议）和二级标签。
- 点击二级标签内联展开匹配原声。
- “查看全部原声”弹窗支持按星级筛选。
- 文件命名：`{ASIN或产品编号}_{产品名}_complaint_analysis.html`

## 原声分页与评论图片

- 每个正面或负面 TOP 主题的“查看原声”必须传入该主题的全量评论，不得只展示 3-4 条样本。
- 原声弹窗每页最多展示 10 条评论；超过 10 条时提供上一页/下一页与当前页、总页数、总条数，星级筛选后重新从第 1 页开始。
- 原声卡片保留星级、日期、标题、原文、中文译文和原评论链接。来源数据含图片数量与评论链接时，尝试从公开评论页提取实际可见的评论图片。
- 仅内嵌成功获取的图片，使用 data URI 保证离线 HTML 可打开；以缩略图显示，点击后在弹窗中放大预览。无法获取的图片不允许用占位图伪造，仍保留图片数量和原评论链接。
- 在概览中说明源数据标记的带图评论数、声明图片数与实际成功内嵌的图片数。

## 注意事项

1. 不要编造产品信息、评分、评论数或销售数据。
2. 对公开网页获取的信息，应优先使用可验证内容；无法获取时写“未获取”。
3. 图片外链若不显示，必须改为下载后内嵌或本地引用。
4. TOP10 百分比必须说明统计口径：单评论主类归因。
5. 如果正面或负面有效主类不足 10 个，展示实际数量即可，不要硬凑无意义类别。
6. 保留原声和中文译文，便于用户核对分类。

## 本工作流补充口径
二级标签必须绑定审核后的评论序号，不能依靠关键词临时搜索替代语义归类。二级允许多标签时明确说明不可相加。无样本的组显示“无可分析样本”，不计算百分比。建议数量以证据为准，不强凑 6-10 条。中文摘要不冒充逐句译文；报告另行生成准确译文。隐私脱敏仅作用于报告展示副本，Excel 原文不改写。图片获取遵守运行环境的媒体限制；不允许下载时保留链接并说明未内嵌。
